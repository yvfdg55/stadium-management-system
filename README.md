# نظام إدارة الملعب

تطبيق Flask عربي لإدارة ملعب، المسؤولين، العملاء، ومواعيد الحجوزات.

## النطاق الحالي

- تسجيل دخول مسؤول وصفحات عربية باتجاه RTL وتصميم متجاوب.
- إدارة العملاء: عرض وبحث وإضافة وتعديل وحذف، مع صفحة لكل عميل تعرض ملخصًا ماليًا وسجل جميع حجوزاته مرتبًا من الأحدث إلى الأقدم.
- تقويم شهري يعرض جميع أيام الشهر مع التنقل بين الأشهر.
- إنشاء حجز بالنقر على ساعة متاحة، مع اختيار العميل والتاريخ ووقت البداية وعدد الساعات وسعر الساعة والملاحظات.
- احتساب وقت النهاية والإجمالي تلقائيًا، والتحقق من صحة ساعات العمل.
- منع الحجوزات المتداخلة في التاريخ نفسه؛ الأوقات المجاورة دون تداخل مسموحة.
- تعديل الحجز وإلغاؤه؛ الإلغاء يحتفظ بسجل الحجز ويحرر الوقت لإعادة الحجز.
- تسجيل دفعات متعددة لكل حجز مع سجلها، واحتساب المدفوع والمتبقي وحالة السداد تلقائيًا.
- إدخال العربون أو المبلغ المدفوع مباشرة من نموذج إنشاء الحجز عند اختيار ساعة متاحة.
- حالة السداد «مدفوع بالكامل» عند اكتمال الإجمالي، و«عربون» قبل ذلك؛ لا يقبل النظام دفعة تتجاوز المتبقي.
- تقارير الحجوزات السارية لليوم والشهر والسنة حسب تاريخ بداية دورة يوم الملعب، مع فترة مخصصة؛ حجوزات ما بعد منتصف الليل تُنسب إلى يوم الدورة الذي بدأت فيه.
- تشمل التقارير عدد الحجوزات وقيمة الإجمالي والمدفوع والمتبقي وعدد الساعات؛ الحجوزات الملغاة مستبعدة.
- صفحة إعدادات لحفظ بيانات الملعب وسعر الساعة ومدة الحجز ونافذة التشغيل في قاعدة البيانات.
- تخصيص اللون الأساسي والثانوي ولون الخلفية من صفحة الإعدادات، وتطبيقها على صفحات التطبيق.
- الإعداد الافتراضي لدورة التشغيل 10:00 إلى 10:00 في اليوم التالي (24 ساعة)، ومدة الحجز الافتراضية ساعة.
- يبدأ تاريخ الحجز يوم الملعب عند وقت بداية التشغيل؛ ساعات ما بعد منتصف الليل تظل ضمن دورة تاريخ بدايتها.
- قاعدة بيانات SQLite تُنشأ تلقائيًا عند التشغيل.

## الهوية وتثبيت التطبيق

- يستخدم التطبيق شعار **Happy Family Resort** المرفق، وأيقونات مناسبة لأحجام التثبيت على الهاتف والحاسوب.
- يتضمن بيان PWA وعامل خدمة، ويمكن تثبيته من المتصفحات الداعمة بعد فتحه عبر HTTPS أو `localhost`.
- تتوفر واجهة العملاء كتطبيق PWA مستقل يبدأ مباشرة من `/public-schedule`، وبنفس شعار وأيقونات Happy Family Resort؛ لا يوجّه العملاء إلى تسجيل دخول الإدارة.
- يحرر المسؤول سياسة العملاء من إعدادات الإدارة؛ تبدأ فارغة وتحجب المواعيد العامة حتى تُملأ. بعد ذلك يجب على العميل الإقرار بأنه قرأ السياسة ووافق عليها قبل عرض الجدول. يسري القبول للجلسة الحالية فقط، ويُطلب مجددًا عند تعديل نص السياسة.
- يعمل التخزين المؤقت للملفات الثابتة العامة فقط؛ لا تُخزّن صفحات الإدارة أو الحجوزات أو أي بيانات عملاء على الجهاز. يلزم الاتصال بالخادم لعرض البيانات وإجراء التغييرات.
- تستلهم لوحة الألوان الأخضر النباتي والذهبي الدافئ والمرجاني من الشعار، مع بقاء خيارات تخصيص الألوان من إعدادات التطبيق.
- عند بدء تشغيل قاعدة بيانات قديمة، تُحدّث قيم الاسم والألوان السابقة الافتراضية فقط؛ وتبقى أسماء المنشآت والألوان التي خصصها المستخدم كما هي.

لا تتضمن النسخة الحالية ردّ مبالغ أو بوابة دفع إلكترونية. مصطلح «عربون» هو حالة سداد عندما يكون المدفوع أقل من الإجمالي.

## التشغيل

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python3 - <<'PY'
from pathlib import Path
import secrets
p = Path('.env')
s = p.read_text().replace('replace-with-a-unique-random-secret-at-least-32-characters', secrets.token_urlsafe(48))
password = secrets.token_urlsafe(24)
s = s.replace('replace-with-a-unique-password-at-least-16-characters', password)
s = s.replace('SESSION_COOKIE_SECURE=true', 'SESSION_COOKIE_SECURE=false')
p.write_text(s)
p.chmod(0o600)
print('Initial admin password:', password)
PY
gunicorn --bind 127.0.0.1:5000 app:app
```

ثم افتح: `http://127.0.0.1:5000/login`.
بعد تسجيل الدخول، شاشة التقويم والحجوزات على: `http://127.0.0.1:5000/admin/booking`.

يمكن تعديل إعدادات الملعب وساعات التشغيل من صفحة **الإعدادات** في لوحة الإدارة. ويُستخدم `HOURLY_RATE` كقيمة ابتدائية فقط عند تهيئة قاعدة بيانات جديدة. يتطلب إنشاء الحجز إضافة العميل أولًا.

## الأمان

يُنشأ حساب المسؤول الأول من `ADMIN_USERNAME` و`ADMIN_PASSWORD` في `.env`، ولا توجد بيانات دخول افتراضية. احتفظ بكلمة المرور المطبوعة عند التهيئة، ثم غيّرها من صفحة الحساب. يتطلب بدء قاعدة بيانات جديدة كلمة مرور أولية فريدة بطول 16 حرفًا على الأقل؛ كلمات مرور الحسابات الجديدة يجب أن تكون 12 حرفًا على الأقل.

رمز الجلسة يُطلب من `.env` ولا توجد قيمة احتياطية معروفة. تُستخدم كوكيز `Secure` و`HttpOnly` و`SameSite=Lax`، ورموز CSRF لكل نماذج POST، وتُحدد محاولات الدخول الخاطئة. أضف اسم النطاق الفعلي إلى `TRUSTED_HOSTS` عند النشر، واستخدم HTTPS وخادم WSGI مثل Gunicorn؛ لا تعرّض خادم Flask التطويري للإنترنت.


`SESSION_COOKIE_SECURE=false` في خطوات التشغيل مخصص لـ`localhost` عبر HTTP فقط؛ عند النشر خلف HTTPS أبقه `true`.


اضبط `TRUSTED_PROXY_HOPS` على عدد الوكلاء العكسيين الذين تثق بهم (0 للتشغيل المحلي المباشر)؛ لا ترفع العدد ما لم تكن كل القفزات الأمامية تحت سيطرتك.
